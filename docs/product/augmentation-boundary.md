# Augmentation boundary

Status: normative · Baseline: `design-v3` · Effective: 2026-08-12 · Owner: product and BA practice councils

CollabX earns competence under evaluation; it does not claim parity with every senior-BA craft. This document classifies tasks as **parity** (system must match or beat baselines), **assist** (system drafts/structures; human owns judgment), or **human-owned** (system must not decide or simulate consent).

## Classification rules

1. If failure harms people, rights, or regulated eligibility → human-owned or Class D prohibited.
2. If IIBA underlying competency is interpersonal/political → assist or human-owned.
3. If task is structural, trace, lint, retrieval, or citation → parity candidate.
4. Progressive autonomy is earned **per action class** under M5; this boundary still applies.

## UX obligations

- Parity features show sources and metrics in plain language.
- Assist features show “draft / proposal” semantics and required human action.
- Human-owned actions cannot be completed by agent terminal success alone.
- Prohibited capabilities are absent from tool catalogs in production profiles.
